## 阅读笔记

### 研究问题

顺序 agent 做长程规划会**约束漂移**（Constraint Drift）：工具返回值越积越多，写在 query 里的总预算被稀释。证据很直接——顺序基线第 1 天预算满足率 98%，第 5 天掉到 42%。

两条旧路线都不行：事后修复（ATLAS）要等整份排完才发现第 1 天超支，延迟超线性增长；端到端 RL（DeepTravel）仍是顺序生成，早期错误会级联。

论文的主张：**在生成过程中就保证约束，而且靠架构而不是靠更大的模型拿收益。**

### 核心方法

一句话：**把长程拆成日级子问题并行求解，再用一个事务性的共享账本把耦合约束焊死。**

**框架上**

1. **分层规划**：协调器负责安排每天的城市、停留或转场，以及每日预算参考；日执行器并行生成各自当天的详细行程。
2. **日执行器之间的上下文隔离**：不直接读取彼此的推理过程和工具调用记录，但不是完全不共享信息。跨天约束通过共享状态协调。
3. **协商式重规划**：执行器发现子任务不可行时，上报结构化原因，比如预算缺口或没有可用住宿；由协调器调整每日预算分配或路线，而不是执行器自行改预算，协商次数设定上限3次。**每日预算是参考，整趟总预算才是硬上限。**
4. **全局统一记账与校验**：采用了一个共享检查器，它维护累计花费、已提交的地点和跨城交通方式，并在提交时拒绝超预算、重复地点或交通方式冲突的安排。

**模型和训练上**

1. **共享一个 Qwen3 模型**：协调器和执行器共享同一套参数，用不同的系统提示词区分角色；各自接收的任务和观测也不同。
2. **GRPO 后训练，按角色设计奖励**：同一任务、同一角色下的 4 条候选轨迹组成一组，每条轨迹都根据自己的得分相对组内均值计算优势，不是只奖励第一名。两种角色都看全局表现；协调器额外看需求提取和重规划次数，执行器额外看当天方案质量和是否尽早发现不可行。
3. **FIFO 节省峰值显存**：准确地说是**哪个角色先攒齐 4 条轨迹，就先用这组轨迹更新共享模型，然后清掉这组数据**。不必等协调器和所有日执行器的轨迹都齐了再更新。

### 主要实验与结论

**消融要对着基线看，不能只看 Δ：**

| 配置             | 分数      | 相对基线（45.56） |
| ---------------- | --------- | ----------------- |
| 完整系统         | 52.78%    | **+7.2**          |
| 去掉协商         | 48.9%     | +3.3              |
| **去掉并行**     | **45.6%** | **≈ 0**           |
| 去掉 Σ           | 43.2%     | −2.4              |
| 去掉 Coordinator | 39.8%     | −5.8              |

Δ 的排序是 −12.98 / −9.58 / −7.18 / −3.88，但"哪个掉得最狠"不等于"哪个贡献最大"。真正的信息在这张对照表里：**只有去掉协商还站在基线之上，去掉其余任何一个都退回基线附近或以下。**

尤其"去掉并行 = 45.6%"几乎等于 DeepTravel 的 45.56%——**说明分层架构的收益是跟并行绑在一起的，一旦顺序化，就退回顺序方案的水平**。所以增益不是某个部件单独带来的，是"分层 + 并行 + 账本"同时成立才有的。

- **FlexTravelBench**：2 轮 44.34%、3 轮 37.42%。**多一轮就掉 7 个点**。
- **效率**：7 天行程 189.5s→72s（2.63×），但 compute 是 210s vs 顺序 190s，token 也更多（14.2k vs 12.3k）——**省的是等待，不是工作量**。

### 个人理解与疑问

**理解**

1. 真正的贡献不是"层级"（MTP 早就有），而是**把硬约束从奖励项搬成了准入条件**。目标函数写"必须成立"，才逼出一个必须会拒绝的组件；如果写成"尽量满足"，整套设计就退化回 ATLAS。
2. 它和 P010 TRIP-PAL 是这条线上的两种对立哲学：一个说"LLM 不该算、交给求解器"，一个说"LLM 可以算、但要加事务锁"。谁对取决于任务能不能写成 PDDL——旅游能，很多真实场景不能。

### 可借鉴之处

1. **硬约束走准入，软约束走奖励。** 凡是"违反即方案作废"的约束，都不要塞进 reward，要写成一个会拒绝的检查点。
2. **多智能体协调优先用结构化信号**：三字段 JSON 回执 + 极简接口，替代自然语言协商。省 token，也少不确定性。
3. **消融要能回答"哪个部件最疼"**：−12.98 / −9.58 / −7.18 / −3.88 这个梯度说明了哪些部分更为重要。
